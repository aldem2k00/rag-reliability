## Что сделать

### 1. `evaluation/protocol.py`

```python
@dataclass(frozen=True)
class CVResult:
    oof_scores: np.ndarray       # (n,) итоговый скор надёжности, out-of-fold
    oof_pred: np.ndarray         # (n,) бинарное решение при OOF-пороге
    y: np.ndarray                # (n,) золото
    ids: list[str]
    per_repeat_f1: list[float]
    thresholds: list[float]      # порог из каждого фолда каждого повтора
    n_excluded: int


def evaluate_cv(samples, predictions, folds, *, score_fn, fit_fn=None,
                grid_step=0.01) -> CVResult:
    """Оценка по фолдам с вложенным подбором порога.

    Для каждого повтора r и фолда k:
        train_idx = все кейсы, кроме фолда k
        test_idx  = фолд k
        если fit_fn задан: model = fit_fn(X[train], y[train])   # стэк, энкодер
        порог подбирается на train_idx, применяется к test_idx
    OOF-предсказания склеиваются; метрика считается ОДИН раз по всем кейсам.

    Кейсы, отсутствующие в folds['assignment'] (oversized-группы), исключаются
    и учитываются в n_excluded — не молча.
    """
```

**Инварианты, которые обязаны быть в коде явными проверками:**

- порог, применённый к фолду `k`, подобран без единого кейса из фолда `k`;
- `score_fn` не имеет доступа к `y`;
- если `fit_fn` задан, он получает только train-индексы;
- при несовпадении sha256 корпуса из `folds.json` с фактическим — ошибка, не предупреждение.

### 2. Одномерный порог

Заменить сетку `t_faith × t_rel` на один порог по `p_reliable`:

```python
def default_score_fn(pred: Prediction) -> float:
    """p_reliable = p_faith * p_rel. Один порог вместо двух.

    Две оси дают квадратичное число кандидатов при линейном приросте
    выразительности, а ось relevance у судьи имеет AUC 0.497 — второй
    порог подбирается по шуму.
    """
```

Per-axis метрики оставить как диагностику, но подбирать для каждой оси **свой** порог отдельно. Сейчас `f1_macro_rel` считается при `t_rel = 0.01`, то есть это метрика константного предсказателя.

### 3. `scripts/evaluate_cv.py`

```bash
python scripts/evaluate_cv.py \
  --data data/organizers.jsonl \
  --folds data/splits/folds.json \
  --scores predictions/m3_judge/zero_shot/scores.jsonl \
  --score-expr "m3.p_faith * m3.p_rel" \
  --compare predictions/alfa/baselines/surface/scores.jsonl \
  --output predictions/m3_judge/zero_shot/report.json
```

`--score-expr` — безопасное выражение по ключам `scores`. Разрешены только имена ключей, числа и операции `+ - * / ( )`. Реализовать через `ast.parse` с белым списком узлов, **не через `eval`**.

`--compare` (можно несколько раз) — парный бутстрэп против указанных прогонов, результат в `report.comparisons`.

### 4. Сборка отчёта

Заполнить `EvaluationReport` (модель из A3):

- `primary` — macro-F1 по `reliable` на OOF, `ci95` из `bootstrap_ci`, `null_percentile` из `nullcal.percentile_of`, `above_noise = null_percentile > 95`;
- `axes` — per-axis macro-F1 с отдельными порогами и своими ДИ;
- `operational` — из `metrics.operational_metrics`;
- `diagnostics` — `degenerate_rate`, `invalid_output_rate`, `thresholds_per_fold`, `threshold_sd`, `sd_across_repeats`;
- `protocol` — путь и sha256 `folds.json`, `n_folds`, `n_repeats`, `n_evaluated`, `n_excluded`;
- `comparisons` — по каждому `--compare`.

**Нулевую калибровку считать той же процедурой**, что применяется к реальным скорам: передать в `null_calibration` свой `fit_apply_fn`. Иначе перцентиль будет от другой процедуры и введёт в заблуждение.

### 5. Режим совместимости

Флаг `--legacy-holdout`, воспроизводящий старую схему (единичный val/test + две сетки порогов). Нужен только для регресс-теста; в отчётах не использовать.

## Тесты

`tests/test_protocol.py`:

- **утечка порога**: искусственные скоры, где идеальный порог в фолде `k` резко отличается от остальных; проверить, что применённый к `k` порог подобран без него;
- `fit_fn` получает только train-индексы (проверить через мок, записывающий переданные индексы);
- исключённые кейсы не попадают в метрику и учтены в `n_excluded`;
- несовпадение sha256 корпуса вызывает ошибку;
- `--score-expr` отвергает `__import__`, атрибуты, вызовы функций;
- детерминированность: два прогона с тем же `folds.json` дают идентичный `report.json` (кроме таймстемпа);
- на константных скорах `above_noise = False`.
