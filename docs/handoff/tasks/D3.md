## Что сделать

### 1. Общий принцип: ноутбук — пусковая установка

Вся логика остаётся в репозитории. Ноутбук делает четыре вещи: поднимает окружение, проверяет железо, поднимает vLLM, вызывает CLI. Это сохраняет `run.yaml` + git-хэш + артефакты — единственное, что в проекте работает безупречно (10 из 10 метрик воспроизвелись до седьмого знака).

**Правило: ни одной строки бизнес-логики в ячейках.** Если чего-то не хватает в CLI — это баг CLI, а не повод писать в ноутбуке.

### 2. `00_setup.ipynb`

```python
BASE   = "/home/jupyter/filestore/neurodrive"
REPO   = f"{BASE}/rag-reliability"
BRANCH = "integration"                      # НЕ qwen7b-notebook

# клон/обновление + pip install -e
# проверка железа с понятным сообщением при неверной конфигурации
# подъём vLLM в фоне с ожиданием готовности и --max-logprobs 25
```

`--max-logprobs 25` обязателен: извлечение вероятностей запрашивает `top_logprobs=20`.

**Смоук на logprobs — отдельная ячейка, обязательная.** Токенизатор vLLM отличается от OpenRouter; при односимвольном подтокене `PASS` извлечение молча вырождается в 0.5 для всех кейсов.

```python

assert all(r["prob_method"] == "logprobs" for r in rows), \

assert len({round(r["scores"]["m3.p_faith"], 3) for r in rows}) > 1, \
    "все вероятности одинаковы — извлечение сломано"
```

### 3. `10_score_judge.ipynb`

Прогоны судьи по всему корпусу через `scripts/score.py` с `--resume`. Варианты: zero_shot, few_shot, разделённые оси, self-consistency, per-chunk. Каждый — отдельная ячейка с ожидаемым временем в комментарии.

После каждого прогона — `git add predictions/... && git commit` прямо из ноутбука, чтобы артефакт не потерялся при обрыве сессии.

### 4. `20_train_encoder.ipynb`

Обёртка над пакетом энкодера из C2. Ключевое: читает `folds.json`, **не вызывает `split_samples`**. Обучает 5 фолдов OOF, пишет `scores.jsonl` с `enc.logit`.

Чекпоинты на File Storage. Контроль схлопывания после каждой эпохи — вывод `const_share` в ячейку, чтобы было видно глазами.

### 5. `30_finetune_judge.ipynb`

Переписать существующий FT-ноутбук:

| Что | Было | Стало |
|---|---|---|
| Ветка клона | `qwen7b-notebook` | `integration` |
| Сплит | `split_samples(samples, seed=SEED)` | чтение `data/splits/folds.json` |
| `SAVE_STRATEGY` | `"no"` | `"epoch"` |
| Баланс классов | несбалансированно | взвешенный лосс + oversampling негативов |
| Выход | генеративный вердикт | вердикт + logprob → `scores.jsonl` |
| Контроль | нет | `degenerate_rate` после каждой эпохи |

Гиперпараметры LoRA (если LoRA, а не full FT): все линейные слои включая MLP, `r=256`, `α=512`, LR ≈ 2e-4 (примерно в 10× выше, чем для full FT). Прошлый прогон на 1.5B схлопнулся в (1,1) из-за дисбаланса — это должно быть невозможно повторить незаметно.

Сохранить рабочие части текущего ноутбука: ассерт на VRAM ≥ 70 GB, 8-bit AdamW, gradient checkpointing, bf16, проверку симметрии формата, экспорт на HF Hub.

    """В 00_setup есть ассерт на prob_method == 'logprobs'."""
