# C4 — Метод 6: NLI-grounding и coverage

**Волна 3** · ветка `task/C4-m6-grounding` · база `integration` (после B2) · спека `docs/specs/40_PHASE3_метод6.md`
**Зависимости:** B2 (`score.py`). **Блокирует:** ничего.
**GPU:** желателен для запуска, но NLI на CPU на 200 кейсах реально — код проверяется на реальных данных без GPU.

---

## Решение

**SelfCheckGPT в текущем виде останавливаем.** Ветка переопределяется: премисой становится чанк контекста, а не сэмпл прокси-модели.

Краткие основания (полные — в спеке `40_PHASE3` §0):

1. Единственное опубликованное число M6 — константный предиктор: `f1_macro_faith = 0.3939…` = ровно **13/33**, порог `t_faith = 0.01` при минимуме `p_faith = 0.4495`, то есть все 20 кейсов помечены достоверными. SelfCheck не участвует ни в одном числе.
2. «Инверсия энтропии −0.164» = **0.38 стандартной ошибки**; знак скачет по порогу кластеризации в собственной таблице абляции команды.
3. SelfCheckGPT требует пересэмплирования *того же* генератора; продакшн-бот закрыт, его промпт не выдан. Прокси измеряет расхождение двух моделей, а не галлюцинацию оригинала.
4. Метод спроектирован для настроек **без** контекста; здесь контекст есть и сэмплер его видит.
5. Цена: ~404 000 NLI-пар и ~37 GPU-ч против ~90 000 пар и ~2 GPU-ч у grounding.

### 2. `grounding.py`

```python
def grounding_features(answer, chunks, nli, *, sentence_splitter=razdel_sentences,
                       entail_threshold=0.5) -> dict[str, float]:
    """Опора ответа на контекст. Премиса — чанк, гипотеза — предложение ответа.

    E, C: матрицы (n_sents, n_chunks)
    per_sent_entail = E.max(axis=1)   лучший источник для предложения
    per_sent_contra = C.max(axis=1)   худшее противоречие
    """
    return {
        "m6.max_entail":       ...,
        "m6.min_entail":       ...,   # СЛАБЕЙШЕЕ ЗВЕНО — целевая фича
        "m6.mean_entail":      ...,
        "m6.mean_contra":      ...,
        "m6.max_contra":       ...,
        "m6.frac_unsupported": ...,   # доля предложений с entail < threshold
        "m6.n_sentences":      ...,
        "m6.chunk_spread":     ...,   # |set(E.argmax(axis=1))| — детектор смешения
    }
```

`m6.min_entail` — главная фича: одно неподкреплённое предложение делает ответ неверным, даже если остальные пять подкреплены. Среднее это размывает.

`m6.chunk_spread` при коротком ответе — подпись `chunk_fact_mixup`.

### 3. `coverage.py`

Ловит то, что entailment невидит по построению: reference-free метрики faithfulness измеряют только **precision** — проверяется сказанное, а не пропущенное. `reason_missed_chunk_conditions` (9 маркеров) и `reason_incomplete_answer` (16) структурно невидимы для grounding.

```python
CONDITION_PATTERNS = [
    r"\bесли\b", r"\bпри условии\b", r"\bне менее\b", r"\bне более\b",
    r"\bдо \d+", r"\bот \d+", r"\bв течение\b", r"\bне позднее\b",
    r"\bтолько для\b", r"\bкроме\b", r"\bминимальн", r"\bмаксимальн",
    r"\d+(?:[.,]\d+)?\s*%", r"\d+\s*(?:руб|₽|дн|мес|год|час)",
]

def coverage_features(answer, chunks, *, source_chunk_ids) -> dict[str, float]:
    """Доля условий из РЕЛЕВАНТНЫХ чанков, отражённых в ответе.

    source_chunk_ids — множество чанков, помеченных grounding как источники
    опоры (E.argmax). Считать по всем 5-8 чанкам бессмысленно: там много
    условий, не относящихся к вопросу.
    """
    return {"m6.n_conditions": ..., "m6.cond_coverage": ...,
            "m6.digit_coverage": ..., "m6.uncovered_max": ...}
```

Coverage считается **после** grounding и переиспользует его матрицу — отдельных NLI-вызовов не требует.

## Тесты

Все на мок-NLI (детерминированная функция вместо модели) — GPU и загрузка весов не нужны.

- `razdel` не режет «макс.», «т.д.», «0.5%», нумерацию шагов — тест на реальном примере из корпуса, ожидается 5 предложений, не 12;
- нормировка: `p_contra` считается по {entail, contra} без neutral;
- окна: `entail` и `contra` берутся из одного окна;
- премиса длиннее `max_length` разбивается на окна, а не усекается до огрызка;
- `grounding_features` возвращает ровно 8 объявленных ключей, все конечны;
- `m6.min_entail` реагирует на одно неподкреплённое предложение среди подкреплённых;
- `m6.chunk_spread` растёт при опоре на разные чанки;
- `coverage_features` находит условия «не менее 100 руб.», «в течение 5 дней», «0.5%»;
- coverage ограничивается `source_chunk_ids`, а не всеми чанками;
- отсутствие ключа фичи вызывает исключение, а не дефолт.

### Принятое решение (интегратор волны 3, после слияния C1–C4)

**Ветка M6 закрывается как направление развития. Задач M6 в волне 4 нет.**

Факт: `m6.min_entail` = 0.548 [0.522, 0.575] на 2233 кейсах — средняя полоса таблицы.
Предписание средней полосы («проверить альтернативные NLI-модели и агрегации»)
выполнено и исчерпано: вторая модель (`rumodernbert-nli`, 0.556 [0.529, 0.583]) внутри
ДИ первой; все агрегации матрицы лежат в 0.461…0.556 и взаимно неотличимы. Решающий
аргумент — стэк: все три M6-фичи дали отрицательное приращение macro-F1 с ДИ поверх
нуля и не прошли правило отбора C1.

Это закрытие **по исчерпанию предписанной проверки**, а не по срабатыванию нижней
строки таблицы: точечная оценка 0.548 в полосу «закрыть количественно» не попадает.
Формулировка для отчёта, числа и полные основания — `docs/report/wave3.md` §4.

Артефакты (12 фич на 2233 кейсах) остаются в `predictions/alfa/m6_grounding/` и
доступны стэку: если появится `enc.logit`, абляция пересчитывается с их участием.
