## Что сделать

### 1. Метрика — главная правка

`gepa.py:58-60` оптимизирует `(ok_faith + ok_rel)/2` — точность по жёстким вердиктам. Отчётная метрика — macro-F1(reliable) по вероятностям с подобранным порогом.

При базовой ставке reliable 72% точность почти плоская: кандидат может улучшить accuracy, чаще отвечая PASS, и одновременно **ухудшить** macro-F1. Ровно это и наблюдалось — все кандидаты жались в 0.617–0.733.

```python
def gepa_metric(example, prediction, trace=None) -> float:
    """Balanced accuracy по оси — устойчива к дисбалансу 72/28 и не требует
    подбора порога внутри цикла оптимизации.

    0.5 * (recall_positive + recall_negative)
    """
```

Альтернатива — macro-F1 с фиксированным порогом 0.5, но balanced accuracy предпочтительнее: она не зависит от калибровки, которая внутри эволюции может дрейфовать.

### 2. Размер валидации

Все четыре закоммиченных отчёта: `train_size: 100, val_size: 30`. Гранулярность скора = 1/60 = 0.0167. «Лучший» кандидат 0.717 против сида 0.683 — это **2 решения из 60**.

При этом `run.yaml` alfa-прогонов заявляет `train_size: 300` — то есть закоммиченные отчёты не от тех прогонов, по которым принимались решения.

Новое: **D_pareto = 300** со стратификацией по классу, train — из train-фолдов текущего фолда `folds.json`. Ни один кейс из held-out не должен попасть в оптимизацию.

### 3. Feedback с диагностикой

`gepa.py:63-65` при ошибке сообщает только правильную метку. Рефлексирующая LM узнаёт *что*, но не *почему*.

```python
def gepa_feedback(example, prediction, *, use_markers: bool) -> str:
    if correct:
        return "Верно."
    parts = [f"Ошибка. Правильный ответ: {axis}={gold}."]
    if use_markers and example.marker:
        parts.append(f"Тип ошибки: {MARKER_GLOSS[example.marker]}.")
    parts.append(f"Фрагмент ответа: «{snippet(example.answer)}».")          # NEW
    parts.append(f"В чанках это не подтверждается / противоречит чанку {i}.")  # NEW
    return " ".join(parts)
```

Последние две строки — то, чего не хватало.

### 5. Синхронизация обучения и инференса

`gepa.py:114-131` эволюционирует инструкцию внутри DSPy-сигнатуры с полями `reasoning/faithfulness/relevance` и адаптерными префиксами. Инференс переносит **только текст инструкции** в рукописный system-промпт с другим ожидаемым форматом вывода. Прямое следствие — сломанный regex-фолбэк и сбитые позиции вердиктов.

После C3 промпты живут в YAML. GEPA должна эволюционировать **тот же YAML**, который читает инференс, а не отдельную DSPy-сигнатуру. Если это невозможно в рамках DSPy — прогонять инференс через тот же DSPy-модуль и зафиксировать это как решение в PR.

### 6. Санитария промптов

В текущих эволюционированных инструкциях вшиты примеры про телескоп «Хаббл», соул-джаз и Парфенон (Википедия, не банк), а в одном — контекст `[Чанк 2] (...)`, то есть судью учат, что чанки бывают пустыми.

Добавить проверку: перед сохранением эволюционированного промпта прогнать детектор посторонних доменов (список стоп-слов из псевдо-корпуса) и предупредить, если сработал.

### 7. Починить отчёт об эволюции

`gepa_report.py:5` (`_EXCERPT = 400`) и `:8-15` (`_candidate_text` берёт первое строковое значение, которым оказывается `repr` объекта `Predict(StringSignature(...))`). В результате у всех кандидатов первые 400 символов идентичны, а изменившаяся середина скрыта.

Показывать **diff между кандидатом и сидом**, а не префикс. Тогда по отчёту будет видно, что именно менялось.

### 8. Протокол H5

| Вариант | Сидов | Данные | Бюджет |
|---|---|---|---|
| markers | 3 (0, 1, 2) | реальный корпус, D_pareto = 300 | `auto=medium` |
| plain | 3 (0, 1, 2) | те же 300 | тот же |

Единственное различие — строка глосса маркера в feedback. Всё остальное идентично.

Сравнение — парный бутстрэп по сидам и по кейсам.

**Стоп-правило:** отвергаем H5, если **верхняя граница** 95% ДИ приращения (markers − plain) < 0. Не «если точечная оценка ниже базовой» — именно это правило и дало ложный отказ в прошлый раз.

Сейчас на реальном корпусе существует только один прогон `gepa_markers_s0` без парного `plain`, а цифра «markers − plain: +0.035 val / −0.005 test» относится к синтетике.

## Тесты

Без dspy (он опционален) — тестировать чистые функции.

- `gepa_metric` даёт 0.5 на константном предсказателе при любом дисбалансе;

- детектор посторонних доменов срабатывает на промпте со словом «Хаббл»;
- `gepa_report` показывает diff, а не идентичные префиксы.
