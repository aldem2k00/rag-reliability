### 2. Промпт relevance — по определению организаторов

Текущий промпт (`prompts.py:15-29`) формулирует relevance как «ответ соответствует вопросу». Определение организаторов жёстче. Обязательные критерии FAIL:

```
  1. Ответ не адресует вопрос клиента.
  2. Ответ отвечает на другой, пусть и смежный, вопрос.
  3. Ответ содержит информацию, предназначенную оператору, а не клиенту
     (служебные пометки, «сообщите клиенту…», инструкции по обработке обращения).
  4. Ответ содержит уточняющий вопрос вместо ответа.
  5. Ответ перенаправляет клиента в статью или на страницу вместо ответа.
  6. Ответ покрывает не все части вопроса, если вопрос состоял из нескольких.
```

И критически важное уточнение, без которого судья будет штрафовать неполноту дважды:

```
Поставь PASS, если ответ по существу решает проблему клиента, даже если он
неполон в деталях. Неполнота по фактам — это ось faithfulness, не твоя.
Учитывай историю диалога: вопрос может быть уточнением предыдущего.
```

Разметка организаторов ставит `1` даже неполному ответу, если он релевантен (их пример: «На 62 дня — 19.84%» на вопрос о ставках).

Ни один из критериев 2–5 в текущем промпте не упомянут, при этом `reason_answer_for_operator` — второй по частоте маркер (27 из 200).

### 4. Промпты — в YAML, не в коде

`configs/prompts/{faithfulness,relevance}.yaml`: system-инструкция, few-shot-примеры, формат вывода, версия. Код читает файл. Это нужно, чтобы D2 (GEPA) мог эволюционировать промпт, не трогая код, и чтобы версия промпта попадала в `run.yaml`.

### 5. Self-consistency

Инфраструктура **есть и не используется**: `judge_client.chat(n=...)` поддерживает `n>1` с деградацией в последовательные вызовы, но `judge()` его не пробрасывает, а `T=0` захардкожен.

```python
def judge_selfconsistent(client, system, user, *, n=8, temperature=0.7) -> dict:
    """N сэмплов -> усреднение вероятностей + доля PASS-голосов.

    scores:
      <axis>.p          среднее по сэмплам (усредняем ВЕРОЯТНОСТИ, не голоса:
                        голоса дают гранулярность 1/N, вероятности непрерывны)
      <axis>.p_vote     доля сэмплов с PASS
      <axis>.p_std      разброс — самостоятельный сигнал трудности кейса
    """
```

`p_std` — отдельная фича для стэка.

**Не менять `judge_client.py`** (владение A4). Если нужна правка — обертка в `selfconsistency.py` поверх публичного `chat(n=...)`, а требуемое изменение описать в PR.

### 6. Criteria injection

`configs/markers.yaml` содержит глоссы 13 маркеров и используется только в feedback GEPA. Превратить в чеклист внутри промпта:

```
Проверь по списку. Если сработал хотя бы один пункт — FAIL, и назови его код.
[13 однострочных критериев]

Формат ответа:
ANALYSIS: <краткий разбор>
MARKER: <код или none>
FAITHFULNESS: PASS|FAIL      (в промпте faithfulness)
```

**Осторожно с форматом.** Добавление `MARKER:` перед вердиктом сдвигает позиции токенов PASS/FAIL. A4 чинит поиск позиций по якорю — убедись, что якорь (`FAITHFULNESS:`) остаётся, и прогони смоук из `90_DATASPHERE_runbook.md` §4 перед полным запуском.
