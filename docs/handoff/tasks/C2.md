## Основание

`deepvk/RuModernBERT-base` имеет `max_position_embeddings = 8192` (проверено по `config.json` на HF). Обучение идёт при `--max-length 512` (`train_encoder_baseline.py:42`) при медианном контексте 6371 символ (~2000–2500 токенов) и p95 12745 символов. **Модель видит меньше четверти входа.**

Вывод в `docs/experiments.md` «Longer context at 1024 hurts macro-F1 because the model becomes too positive» построен на прогоне, который **выродился**: recall = 1.0000, macro-F1 = 0.4191 — класс схлопнулся в «всё надёжно». Это провал обучения, а не свойство длины. Вывод снимается.

## Что сделать

### 1. Вынести из скрипта в пакет

Сейчас вся логика в `scripts/train_encoder_baseline.py` — не тестируется, не переиспользуется, содержит собственный сплит. Разнести:

- `data.py` — построение текстового входа, токенизация, `Dataset`;
- `train.py` — цикл обучения, контроль схлопывания, чекпоинты;
- `predict.py` — инференс, запись `scores.jsonl` с ключом `enc.logit`;
- скрипт остаётся тонкой обёрткой над `train.py`.

### 2. Читать `folds.json`, а не сплитить

`train_encoder_baseline.py:107` вызывает `split_samples` — это четвёртый протокол сплита в кодовой базе (1571/225/449). Убрать полностью.

```python
def train_oof(samples, folds, config, *, repeat=0) -> dict[str, float]:
    """Обучает n_folds моделей, каждая предсказывает свой held-out фолд.
    Возвращает OOF-логиты по всем кейсам -> scores['enc.logit'].
    """
```

**Компромисс по стоимости.** Полный 5×5 OOF — это 25 обучений (~50 GPU-ч), неприемлемо. Делать **5 фолдов без повторов** (~10 GPU-ч), разброс оценивать бутстрэпом по кейсам. В `run.yaml` и `report.json` записать `n_repeats: 1` явно, чтобы при сравнении с другими методами это было видно.

### 3. Формат входа

`prepare_data.py:93,111` кладёт `[CHUNK i]` латиницей и весь `full_dialog` в `question`. В ветке `m3-m6` было `[Чанк i]` и явное разделение «История диалога / Текущий вопрос». Привести к последнему:

```
История диалога:
{диалог без последней реплики клиента}

Текущий вопрос: {последняя реплика клиента}

[Чанк 1]
{...}
[Чанк 2]
{...}

Ответ бота:
{answer}
```

Разделители чанков обязательны: без них модель не может отличить границы источников, а `chunk_fact_mixup` — один из двух главных типов ошибок.

### 4. Контроль схлопывания

**Обязательно.** После каждой эпохи логировать `degenerate_rate` (из `metrics.py`, A2). Прогон с `const_share > 0.98` помечается `collapsed: true` в `run.yaml` и **исключается из выбора лучшей конфигурации**.

Именно на таком прогоне был сделан прежний вывод про 1024 токена.

### 5. Сетка экспериментов

| Ось | Значения |
|---|---|
| `max_length` | 512 (контроль), 2048, 4096, 8192 |
| LR | 2e-5; для 4096/8192 добавить 1e-5 |
| `warmup_ratio` | 0.06 — сейчас отсутствует, добавить |
| batch × grad_accum | подобрать под VRAM; на A100 80GB для 8192 ориентир bs=1, accum=8 |
| class weighting | `none`, `pos_weight = n_neg / n_pos` |

Отбор лучшей конфигурации — **по OOF-метрике с ДИ**, а не по максимуму. При 7 конфигурациях и n≈2100 ожидаемый оптимизм отбора max-из-7 порядка +0.015 — указать это в отчёте.

## Тесты

Все — **без загрузки реальных весов**. Использовать крошечную модель-заглушку (`hf-internal-testing/tiny-random-*` или локальный мок).

- построение текстового входа: разделители чанков присутствуют, диалог и текущий вопрос разделены;
- усечение по `max_length` не режет ответ бота (ответ идёт последним — проверить, что при переполнении режется контекст, а не ответ);
- `train_oof` не даёт модели фолда `k` ни одного кейса из фолда `k` (мок, записывающий индексы);
- `degenerate_rate` вызывается после каждой эпохи и попадает в лог;
- конфигурация с искусственно вырожденными предсказаниями помечается `collapsed: true`;
- `predict.py` пишет `scores.jsonl` с ключом ровно `enc.logit` и без `faithfulness_pred != 0`;
- `split_samples` не вызывается нигде в пакете (тест на отсутствие импорта).

## Если 8192 не помогает

Прежде чем отказываться, проверить две гипотезы:

1. **Позиционный bias (lost-in-the-middle).** Перемешать порядок чанков и посмотреть дисперсию предсказания. Единственная непроверенная гипотеза из аудита.
2. **Per-chunk агрегация вместо склейки.** 8 независимых проходов по 1024 токена с агрегацией max/attention. Дешевле по памяти и даёт per-chunk атрибуцию — тот же механизм, что в D1.
