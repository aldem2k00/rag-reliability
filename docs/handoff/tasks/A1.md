### 2. Обработка oversized-групп

Крупнейшая группа по нормализованному вопросу — `оператор`, 136 строк (6.1% корпуса). После склейки по `chunk_1` она вырастет.

Правило: если группа > 15% корпуса, она **не разбивается**, помечается `oversized`, целиком уходит в train во всех повторах, а её кейсы **исключаются из метрики** (отсутствуют в `assignment`). Число исключённых пишется в `stats.excluded_ids` и обязано попадать в отчёты.

Без этого один фолд станет несравним с остальными.

### 3. Производительность

2233² пар для near-duplicate — не держать в памяти целиком. Считать `cosine_similarity` блоками по 500 строк, брать только пары выше порога.

### 4. `scripts/prepare_splits.py`

Два режима:

```bash
python scripts/prepare_splits.py --data data/organizers.jsonl --output data/splits/folds.json
python scripts/prepare_splits.py --check --folds data/splits/folds.json --data data/organizers.jsonl
```

`--check` возвращает код 1 при провале любой блокирующей проверки:

| Проверка | Порог | Блокирует |

| sha256 корпуса совпадает | точно | да |

| near-duplicate (cos ≥ 0.9) между фолдами | < 2% | да |
| отклонение base rate по фолдам от 72.25% | ≤ 2 п.п. | да |
| `chunk_1` между фолдами | < 5% | нет (warning) |
| отклонение размера фолда | ≤ 5% | нет (warning) |

## Тесты

`tests/test_splits.py`:

- `normalize_query` схлопывает регистр, пунктуацию, пробелы; идемпотентна;
- `extract_last_client_turn` возвращает последнюю реплику, `None` при отсутствии;
- union-find транзитивен: A~B, B~C ⟹ A,C в одной группе;
- `assign_folds` детерминирована: два вызова с тем же seed дают идентичный результат;
- ни одна группа не расщеплена между фолдами внутри одного повтора;
- base rate по фолдам в пределах допуска на синтетическом наборе с известным дисбалансом;
- oversized-группа отсутствует в `assignment` и присутствует в `stats.oversized_groups`;
- `check_folds` ловит подделанный `assignment` (перенос одного id в другой фолд).
