## Что сделать

### 1. `scripts/make_leaderboard.py`

Обходит `predictions/**/report.json`, собирает таблицу:

```bash
python scripts/make_leaderboard.py --root predictions --output docs/report/leaderboard.md
```

Обязательные колонки:

| Метод | reliable F1 | 95% ДИ | перц. шума | AUC | PR-AUC (unrel) | lift | R@P=0.6 | % помечено | n |
|---|---|---|---|---|---|---|---|---|---|

**Жёсткие правила сборки:**

- прогон без `ci95` в отчёте **не попадает в таблицу** — вместо строки печатается предупреждение;
- прогоны с разным sha256 `folds.json` **не попадают в одну таблицу** — это главный класс ошибок, который был в проекте (числа с четырёх протоколов в одной таблице);
- строки с `null_percentile < 95` помечаются серым/значком «неотличимо от шума»;
- `partial: true` прогоны — отдельной секцией с явным `n`;
- прогоны на `predictions/pseudo_debug/**` в основной лидерборд **не входят** вообще.

### 2. Матрица попарных сравнений

Отдельная таблица: парный бутстрэп каждого метода против стэка и против surface-бейзлайна.

| A vs B | Δ | 95% ДИ | p | Значимо |
|---|---|---|---|---|

Правило подачи: если ДИ пересекает ноль — в колонке «Значимо» стоит «нет», и это **не прячется** в сноску.

### 3. Графики

Три обязательных, все с ДИ:

1. **Лидерборд с усами** — точечная оценка + 95% ДИ по методам, вертикальная линия p95 нулевой калибровки. Сразу видно, какие методы выше шума.
2. **PR-кривые по классу unreliable** для топ-5 методов + горизонталь base rate. Показывает эксплуатационную ценность, которую macro-F1 скрывает.
3. **Абляция стэка** — вклад каждой фичи с ДИ приращения.

Не рисовать столбики без усов. Это главный визуальный дефект прежних отчётов.

### 4. Переписать `docs/experiments.md`

Полностью. Структура:

- **Протокол** — один канонический сплит, sha256, 5×5 CV, вложенный порог. Со ссылкой на `folds.json`.
- **Нулевая калибровка** — что даёт чистый шум через ту же процедуру. Печатается один раз в начале и служит опорой для чтения всех таблиц.
- **Лидерборд** — включается из сгенерированного файла.
- **Попарные сравнения**.
- **Абляции** — стэк, self-consistency по N, энкодер по длине контекста, H5.
- **Снятые числа** — таблица «что было, почему снято, где пересчитано». Из результата A5.

### 6. Три результата, которые надо вынести вперёд

Не как оправдания, а как вклад:

1. **Измеренная цена утечки.** Под стратифицированным сплитом 1-NN-запоминатель даёт 0.6278 — выше дообученного энкодера (0.5879) на том же протоколе; под group-aware падает до 0.5125. Обоснование протокола, а не признание ошибки.
2. **Нулевая калибровка процедуры подбора порогов.** Генератор случайных чисел через ту же процедуру даёт val-p95 = 0.5947 и test-p95 = 0.5488. Такую проверку почти никто не делает.
3. **Ортогональность судьи.** Prompted judge не превосходит поверхностный бейзлайн как самостоятельный детектор, но его faithfulness-сигнал независим: стэк даёт +0.029 (0.5798 → 0.6085, 5×5 CV, σ = 0.007). Негативный результат H1 превращается в позитивный результат про ансамблирование.

## Тесты

- лидерборд не включает прогон без `ci95`;
- лидерборд отказывается смешивать прогоны с разными sha256 фолдов (падает с понятной ошибкой);
- `pseudo_debug/**` не попадает в основную таблицу;
- `null_percentile < 95` помечается;
- `partial` прогоны в отдельной секции;
- графики генерируются без исключений на подготовленном наборе отчётов;
- сгенерированный markdown валиден (парсится).
