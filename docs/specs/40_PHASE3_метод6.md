# 40 — Фаза 3: Метод 6, переопределение

**Цель:** сохранить вклад ветки, убрав из петли прокси-генератор.
**GPU:** ~2 часа. **Оценка:** 1 неделя. **Предусловие:** фазы 0 и 1 закрыты. Параллельна фазе 2.

---

## 0. Решение и его обоснование

**SelfCheckGPT в текущем виде останавливаем. Ветка переопределяется в NLI-grounding ответа против чанков.**

Шесть оснований, по убыванию тяжести:

1. **Единственное существующее число M6 не измеряет M6.** `f1_macro_faith = 0.3939393939…` = ровно **13/33** — это macro-F1 константного предиктора «всё достоверно» на 20 кейсах. Порог `t_faith = 0.01` при минимуме `p_faith = 0.4495` ⟹ все 20 помечены достоверными. `f1_macro_reliable = 0.5959…` = 59/99 — чистый результат supervised-логрега `p_rel`, обученного на 20 кейсах. SelfCheck не участвует ни в одном опубликованном числе.

2. **Главный негативный вывод не выдерживает проверки.** «Инверсия энтропии −0.164» составляет **0.38 стандартной ошибки** (SE ≈ 0.433 при 20 кейсах). Знак скачет по порогу кластеризации в собственной таблице абляции команды: при N=5 он −0.065 (thr 0.5), +0.017 (thr 0.4), +0.065 (thr 0.3). Смещение plug-in оценки энтропии при N=6 против N=11 воспроизводит «инверсию» механически, без всякого «alignment collapse».

3. **Валидность подорвана в основании.** SelfCheckGPT требует пересэмплирования *того же генератора*. Ответы произведены закрытым продакшн-ботом, его промпт не выдан (вопрос кураторам не закрыт), сэмплы берутся у `qwen-2.5-7b-instruct` с выдуманным промптом. Измеряется не «галлюцинирует ли ответ», а «расходятся ли две разные модели». На классе `reason_answer_for_operator` (27 из 200 маркеров — стилевой паттерн конкретного бота) это даст систематическое ложное срабатывание.

4. **Метод применён вне своей области.** SelfCheckGPT спроектирован как zero-resource метод для настроек **без** контекста. Здесь контекст есть, сэмплер его видит (`BOT_USER` подставляет `{ctx}`), и consistency почти полностью перекрывается прямым entailment против контекста.

5. **Цена не оправдана.** ~37 GPU-ч на полный корпус при N=10 (404 000 NLI-пар с окнами) под фичу с нулевым продемонстрированным вкладом.

6. **Литература против.** Два независимых свидетельства: supervised-энкодеры бьют сэмплинговые UQ-методы (MSP/CCP/Focus) на span-детекции галлюцинаций; consistency-признаки дают AUROC 0.556 и **меняют знак** между семействами моделей — в grounded-режиме галлюцинация лингвистически мимикрирует под контекст.

**Что при этом сохраняется:** вся NLI-инфраструктура, оконная нарезка, сентенизация, дисциплина кэшей и абляций. Переопределение — это не отказ от работы, а смена того, что подаётся на вход NLI.

## 1. Задача 3.1 — NLI-grounding вместо SelfCheck

### 1.1 Схема

```
        SelfCheck (было)                    Grounding (стало)
  premise  = сэмпл прокси-модели       premise  = чанк контекста
  hypothesis = предложение ответа      hypothesis = предложение ответа
  ──────────────────────────────       ──────────────────────────────
  требует генератора                   генератора нет вообще
  N=10 сэмплов × 512 токенов           0 генераций
  (предл. × N) + (N+1)² пар            предл. × n_chunks пар
  ≈ 181 пар/кейс, 404k на корпус       ≈ 40 пар/кейс, 90k на корпус
  измеряет расхождение двух моделей    измеряет опору ответа на источник
```

### 1.2 Модуль `src/rag_reliability/methods/m6/grounding.py`

```python
"""NLI-обоснованность ответа относительно retrieved-чанков.

Заменяет SelfCheck-ветку: премиса — чанк, гипотеза — предложение ответа.
Генератор из петли исключён, поэтому вопрос о прокси-модели не возникает.
"""

def grounding_features(
    answer: str,
    chunks: list[str],
    nli: NLIScorer,
    *,
    sentence_splitter=razdel_sentences,
    entail_threshold: float = 0.5,
) -> dict[str, float]:
    """Скалярные фичи опоры ответа на контекст.

    Для каждого предложения ответа s и каждого чанка c считается (entail, contra).
    Агрегация по чанкам — max по entail (достаточно одного источника опоры),
    затем агрегация по предложениям.
    """
    sents = sentence_splitter(answer)
    # матрица (n_sents, n_chunks)
    E, C = score_matrix(sents, chunks, nli)
    per_sent_entail = E.max(axis=1)          # лучший источник для предложения
    per_sent_contra = C.max(axis=1)          # худшее противоречие
    return {
        "m6.max_entail":       float(per_sent_entail.max()),
        "m6.min_entail":       float(per_sent_entail.min()),   # слабейшее звено
        "m6.mean_entail":      float(per_sent_entail.mean()),
        "m6.mean_contra":      float(per_sent_contra.mean()),
        "m6.max_contra":       float(per_sent_contra.max()),
        "m6.frac_unsupported": float((per_sent_entail < entail_threshold).mean()),
        "m6.n_sentences":      float(len(sents)),
        # детектор смешения источников: разные предложения опираются на разные чанки
        "m6.chunk_spread":     float(len(set(E.argmax(axis=1)))),
    }
```

**`m6.min_entail` — целевая фича.** «Слабейшее звено» ответа: одно неподкреплённое предложение делает ответ неверным, даже если остальные пять подкреплены. Среднее это размывает.

**`m6.chunk_spread`** — сколько разных чанков служат опорой разным предложениям. Высокое значение при коротком ответе — подпись `chunk_fact_mixup`.

### 1.3 Что починить перед первым замером

Иначе абляция снова измерит баги, а не метод.

| # | Что | Где | Как |
|---|---|---|---|
| а | Вернуть `razdel` вместо регулярки | `thr/.../m6/features.py:18` | регулярка режет «макс.», «т.д.», «0.5%» и нумерацию шагов: 12 «предложений» вместо 5 |
| б | Вернуть оконный NLI с перекрытием | `thr/.../m6/nli.py:39-46` | сейчас просто `truncation=True`; чанки бывают длиннее 512 токенов |
| в | Починить `_MIN_BUDGET` | `m3m6/.../m6/nli.py:81-86` | усечение премисы до 32 токенов делает результат функцией длины гипотезы |
| г | `max` по окнам — согласованно для entail и contra | `m3m6/.../m6/nli.py:48-49` | брать пару из окна с максимальным `entail`, а не два независимых максимума |
| д | Нормировка P(contradict) по {entail, contra} | `thr/.../m6/nli.py:47-53` | сейчас трёхклассовый softmax, neutral съедает массу: медиана contra = 0.0099 |
| е | Убрать молчаливые дефолты | `thr/.../m6/predict.py:41-43` | отсутствие фичи должно быть ошибкой, а не «идеально надёжным кейсом» |

Пункт (г) в grounding-схеме особенно важен: премиса (чанк) длинная, гипотеза (предложение) короткая, значит окон много и `max`-агрегация по ним систематически завышает и entail, и contra.

## 2. Задача 3.2 — AUC до порогов

Сейчас в проекте **не существует ни одного ROC-AUC для M6** — ни на val, ни на test, ни на псевдо-корпусе. Всё меряется macro-F1 после подбора двух-трёх порогов на 20 точках, то есть метрикой, которая шумит сильнее сигнала.

```bash
python scripts/score_m6_grounding.py \
  --data data/organizers.jsonl --nli-model MoritzLaurer/mDeBERTa-v3-base-xnli... \
  --output predictions/m6_grounding/base/scores.jsonl

python scripts/evaluate_cv.py \
  --scores predictions/m6_grounding/base/scores.jsonl \
  --score-expr "m6.min_entail" --folds data/splits/folds.json \
  --output predictions/m6_grounding/base/report.json
```

Один прогон по всем 2233 с ROC-AUC и бутстрэп-ДИ отвечает на вопрос «есть ли сигнал» за ~10 минут и без единого порога.

**Правило принятия решения:**

| Результат | Действие |
|---|---|
| AUC ≥ 0.60, нижняя граница ДИ > 0.55 | фича идёт в стэк, ветка развивается |
| AUC 0.53–0.60 | проверить альтернативные NLI-модели и агрегации, потом решать |
| AUC ≤ 0.53, верхняя граница ДИ < 0.57 | **закрыть количественно** — это защитимый негативный результат |

Последняя строка — тоже результат, и её надо быть готовым принять.

## 3. Задача 3.3 — детектор пропущенных условий (coverage)

**Ожидаемый эффект: закрывает тип ошибки, невидимый для entailment. Стоимость: 1 день, GPU не нужен.**

### 3.1 Почему это отдельная задача

Reference-free метрики faithfulness измеряют только **precision**: проверяется то, что сказано, а не то, что пропущено. Уклончивый и неполный ответ получает высокий скор. `reason_missed_chunk_conditions` (9 маркеров) и `reason_incomplete_answer` (16) структурно невидимы для NLI-grounding.

### 3.2 Модуль `m6/coverage.py`

```python
CONDITION_PATTERNS = [
    r"\bесли\b", r"\bпри условии\b", r"\bне менее\b", r"\bне более\b",
    r"\bдо \d+", r"\bот \d+", r"\bв течение\b", r"\bне позднее\b",
    r"\bтолько для\b", r"\bкроме\b", r"\bисключая\b", r"\bминимальн", r"\bмаксимальн",
    r"\d+(?:[.,]\d+)?\s*%", r"\d+\s*(?:руб|₽|дн|мес|год|час)",
]

def coverage_features(answer: str, chunks: list[str], *, relevant_chunk_ids=None) -> dict:
    """Доля условий из релевантных чанков, отражённых в ответе.

    Условие считается покрытым, если его числовое ядро или ключевая лемма
    присутствует в ответе. Грубая эвристика — но она ловит ровно тот класс,
    который entailment пропускает по построению.
    """
    return {
        "m6.n_conditions": ...,        # сколько условий найдено в чанках
        "m6.cond_coverage": ...,       # доля покрытых
        "m6.digit_coverage": ...,      # доля чисел из чанков, попавших в ответ
        "m6.uncovered_max": ...,       # «важность» самого крупного пропущенного условия
    }
```

**Ограничение области.** Считать покрытие по **всем** чанкам бессмысленно: 5–8 чанков содержат много условий, не относящихся к вопросу. Ограничивать множеством чанков, которые NLI-grounding пометил как источники опоры (`E.argmax` из 3.1). То есть coverage считается **после** grounding и переиспользует его матрицу.

### 3.3 Проверка

Целевая проверка — не общий AUC, а recall на подгруппах `reason_missed_chunk_conditions` (n=9) и `reason_incomplete_answer` (n=16). Обе подгруппы малы: обязательно ДИ Уилсона и пометка `underpowered: true`. Реалистичная задача здесь — не доказать эффект, а показать направление и заложить фичу в стэк.

## 4. Задача 3.4 — контрастное сэмплирование (опционально)

**Единственная форма сэмплирования, несущая в RAG непокрытую информацию.**

Если хочется сохранить сэмплинговую ветку ради полноты сравнения методов:

```
ответ_с_контекстом  = sample(вопрос + чанки)     ← как сейчас
ответ_без_контекста = sample(вопрос)             ← НОВОЕ

m6.parametric_leak = similarity(ответ_бота, ответ_без_контекста)
                   - similarity(ответ_бота, ответ_с_контекстом)
```

Высокое значение означает: ответ бота ближе к тому, что модель говорит **без источника**, чем к тому, что она говорит **по источнику** — то есть ответ взят из параметрической памяти, а не из документов. Это прямой признак необоснованности, которого нет ни у судьи, ни у LettuceDetect.

Стоимость вдвое выше обычного сэмплирования. Запускать только после того, как 3.1–3.3 дали числа, и только если остаётся бюджет.

**Что при этом всё равно нельзя утверждать:** это по-прежнему прокси-генератор, не бот. Формулировка в статье должна это оговаривать.

## 8. Что писать в статью

Переопределение — сильная позиция, если подать его как измерение, а не как отступление:

> Мы реализовали SelfCheckGPT в полном объёме и обнаружили, что в grounded-постановке метод неприменим по двум независимым причинам. Во-первых, он требует пересэмплирования того же генератора, который произвёл ответ; в продакшн-сценарии генератор закрыт, и прокси-модель измеряет расхождение двух разных систем, а не галлюцинацию оригинала. Во-вторых, сэмплер обусловлен тем же контекстом, что и оригинал, поэтому consistency-сигнал почти полностью перекрывается прямым entailment ответа против контекста. Мы переопределили ветку как NLI-grounding, что сократило вычислительную стоимость с 404 тыс. до 90 тыс. пар на корпус, устранило зависимость от недоступного генератора и позволило впервые измерить ROC-AUC этой ветки.

Плюс отдельным абзацем — воспроизводимый негативный результат про энтропию с честной оценкой мощности вместо интерпретации шума.
