## 1. Диагноз, из которого следует архитектура

Три структурные проблемы текущего кода, каждая из которых лечится не патчем, а изменением контура:

**П1. Инференс склеен со сплитом.** Каждый метод пишет `val.jsonl` и `test.jsonl` — то есть предсказания физически привязаны к конкретному разбиению. Следствие: в кодовой базе четыре несовместимых протокола сплита (`dataset.py:42`, `m3m6/.../make_splits.py:57`, `train_encoder_baseline.py:107`, `make_splits.py:82`), числа из них попадают в общие таблицы, а смена протокола требует перепрогона всех методов.

**П2. Контракт предсказания слишком узкий.** `Prediction` (`schema.py:57-75`) несёт две бинарные метки и две вероятности. Методы, которые по природе своей выдают *признаки*, а не решения — LettuceDetect, NLI-grounding, coverage, SelfCheck, — вынуждены притворяться классификаторами: каждый заводит свои пороги, свою калибровку и свою голову. Отсюда `m6/predict.py:36-45` с тремя хардкод-порогами и `ablation.py:73-83` с перебором трёх порогов на 223 строках.

**П3. Оценка не отделена от подбора.** Порог фитится на том же val, на котором отчитываются (`m3m6/.../eval_local.py:26-40`), а сетка 99×99 на 223 строках с 55 негативами даёт систематический оптимизм +0.035…+0.053 — больше, чем любая разница между методами в проекте.

Архитектура ниже устраняет все три.

## 2. Целевая архитектура

### 2.1 Главный принцип

> **Метод производит скоры по всему корпусу. Сплит применяется на этапе оценки, а не инференса.**

Один метод — один артефакт `scores.jsonl` на 2233 строки. Любой протокол оценки (holdout, 5×5 CV, group-aware, стратифицированный) — это функция от `(scores.jsonl, folds.json)`. Смена протокола перестаёт требовать перепрогона моделей; сравнение методов между собой становится корректным по построению.

Для необучаемых методов (prompted judge, zero-shot NLI, surface без обучения) это буквально прогон по всем 2233. Для обучаемых (энкодер, LoRA-судья, стэк, логрег) — **out-of-fold** предсказания: модель обучается на train-фолдах, предсказывает свой held-out фолд, скоры склеиваются в тот же файл на 2233 строки.

### 2.3 Расширенный контракт предсказания

```python
class Prediction(BaseModel):
    id: str
    faithfulness_pred: int = Field(ge=0, le=1)   # контракт платформы, остаётся
    relevance_pred: int = Field(ge=0, le=1)
    marker_pred: str | None = None
    raw_output: str | None = None
    invalid_output: bool = False
    faithfulness_prob: float | None = Field(default=None, ge=0, le=1)
    relevance_prob: float | None = Field(default=None, ge=0, le=1)
    prob_method: str | None = None
    # NEW: открытый словарь скалярных сигналов метода.
    # Ключи именуются "<метод>.<сигнал>", чтобы стэкер собирал их без коллизий.
    scores: dict[str, float] = Field(default_factory=dict)
```

Примеры содержимого `scores`:

| Метод | Ключи |
|---|---|
| `m3_judge` | `m3.p_faith`, `m3.p_rel`, `m3.n_pass_votes`, `m3.max_chunk_score`, `m3.chunk_disagreement` |
| `m6_grounding` | `m6.max_entail`, `m6.min_entail`, `m6.mean_contra`, `m6.frac_unsupported` |
| `m6_coverage` | `m6.cond_coverage`, `m6.n_conditions` |
| `lettucedetect` | `ld.max_unsup`, `ld.mean_unsup`, `ld.frac_unsup` |
| `encoder` | `enc.logit` |
| `surface` | `surf.p_faith`, `surf.p_rel`, `surf.len_ratio`, `surf.digit_match` |

Обратная совместимость: `faithfulness_prob`/`relevance_prob` сохраняются, `scores` — дополнение. Существующие 22 файла предсказаний читаются без изменений.

### 2.4 Протокол оценки

```
folds.json ──┐
             ├──► protocol.evaluate_cv(scores, folds)
scores.jsonl ┘         │
                       ├── для каждого repeat r ∈ 1..5:
                       │     для каждого fold k ∈ 1..5:
                       │       train = фолды ≠ k  → фитим порог (и стэкер) ЗДЕСЬ
                       │       test  = фолд k     → применяем, копим предсказания
                       ├── склеиваем OOF-предсказания по всем 2233
                       ├── метрики + бутстрэп-ДИ по 2233
                       └── нулевая калибровка той же процедуры
```

Ключевые свойства:

- **Порог никогда не фитится на данных, на которых отчитываются.** Внутри каждого фолда порог подбирается на train-части, применяется к held-out части.
- **Метрика считается по всем 2233 кейсам**, а не по 223. Ширина ДИ падает примерно втрое: с ±0.070 до ±0.022.
- **Разброс сплита усредняется** по 5 повторам. sd единичного сплита — 0.032; после усреднения по 25 фолдам — порядка 0.007.
- **Нулевая калибровка считается автоматически** и печатается рядом с каждым числом: «шум той же процедуры даёт p95 = X».

### 2.5 Единый порог вместо двух

Сейчас: сетка `t_faith × t_rel` = 10 201 кандидат (`thresholds.py:78-88`).
Целевое: `p_reliable = p_faith · p_rel`, одномерная сетка, 101 кандидат.

Обоснование: две оси дают квадратичное число кандидатов при линейном приросте выразительности, а ось relevance у судьи имеет AUC 0.497 — то есть второй порог подбирается по шуму. Per-axis метрики остаются как диагностика, но считаются при **отдельно подобранных** для каждой оси порогах, а не при совместных (сейчас `f1_macro_rel` при `t_rel = 0.01` — метрика константного предсказателя).

### 2.6 Что становится невозможным по построению

| Ошибка | Почему больше не случится |
|---|---|
| Числа с разных сплитов в одной таблице | Сплит один, лежит в `folds.json`, читается всеми |
| Val-числа выданы за test | В отчёте есть только OOF-числа по всем 2233 |
| Порог подобран и отчитан на одних данных | `protocol.py` физически разделяет фит и применение |
| Метод сравнивается сам с собой на другом протоколе | Все `scores.jsonl` — по одному и тому же корпусу |
| Отчёт без доверительного интервала | `report.json` без ДИ не собирается (валидация в схеме) |

## 4. Сквозные требования

Действуют во всех фазах. Нарушение — блокер на ревью.

**Т1. Ни одного числа без интервала.** Точечная оценка в отчёте, таблице или коммит-сообщении сопровождается 95% ДИ. Для сравнений — парный бутстрэп и p-value.

**Т2. Ни одного решения по разнице внутри шума.** Стоп-правила формулируются в терминах ДИ: «отвергаем, если верхняя граница ДИ приращения ниже 0» — а не «отвергаем, если точечная оценка ниже базовой». Прошлое стоп-правило по GEPA сработало на Δ = +0.0216 при ДИ [−0.037, +0.100].

**Т3. Артефакт или не было.** Число, не имеющее `scores.jsonl` + `report.json` + `run.yaml` рядом, не попадает ни в одну таблицу. Сейчас так живёт хедлайн энкодера 0.5879: `results/` пуст.

**Т4. Кэш инвалидируется при смене семантики.** Ключ кэша включает: модель, промпт, `max_tokens`, `temperature`, `top_p`, `api_base`, **версию кода извлечения**. Кэш хранит **сырые** logprobs, а не выведенные вероятности — иначе починка извлечения невидима.

**Т5. Синтетика отделена физически.** `predictions/pseudo_debug/**` для псевдо-корпуса, `predictions/alfa/**` для реальных данных. Никаких `cloud/` рядом с `alfa_openrouter/`.

**Т6. `run.yaml` фиксирует грязное дерево.** `git_hash()` дополняется `git status --porcelain`; при непустом выводе пишется `dirty: true` и список файлов.

**Т7. Отчётность включает эксплуатационные метрики.** Помимо macro-F1: PR-AUC по классу unreliable с указанием base rate и lift, recall@precision на 2–3 рабочих точках, доля помеченного трафика, degenerate-output rate.

## 6. Что из этого попадает в статью

Фазы производят не только числа, но и три методологических результата, которые сильнее текущих формулировок:

1. **Измеренная цена утечки.** Под стратифицированным сплитом тривиальный 1-NN даёт 0.6278 — выше дообученного энкодера (0.5879) на том же протоколе; под group-aware падает до 0.5125. Это подаётся как обоснование протокола, а не как признание ошибки.
2. **Нулевая калибровка процедуры подбора порогов.** Показать, что генератор случайных чисел через ту же процедуру даёт val-p95 = 0.5947 и test-p95 = 0.5488. Такую проверку почти никто не делает, и она объясняет, почему часть «результатов» в области невоспроизводима.
3. **Ортогональность судьи.** Prompted judge не превосходит поверхностный бейзлайн как самостоятельный детектор, но его faithfulness-сигнал независим: стэк даёт +0.029 macro-F1 (0.5798 → 0.6085, 5×5 CV, σ = 0.007). Негативный результат H1 превращается в позитивный результат про ансамблирование, без приукрашивания.
